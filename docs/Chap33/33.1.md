## 33.1-3

> The **_polar angle_** of a point $p_1$ with respect to an origin point $p_0$ is the angle of the vector $p_1 - p_0$ in the usual polar coordinate system. For example, the polar angle of $(3, 5)$ with respect to $(2, 4)$ is the angle of the vector $(1, 1)$, which is $45$ degrees or $\pi / 4$ radians. The polar angle of $(3, 3)$ with respect to $(2, 4)$ is the angle of the vector $(1, 1)$, which is $315$ degrees or $7\pi / 4$ radians. Write pseudocode to sort a sequence $\langle p_1, p_2, \ldots, p_n \rangle$ of $n$ points according to their polar angles with respect to a given origin point $p_0$. Your procedure should take $O(n\lg n)$ time and use cross products to compare angles.

Use any $O(n \lg n)$ comparison-based sorting algorithm, where cross-product sign is used for comparison. This will produce an ascending sequence of polar angles.

The sign of a cross product alone is not a valid comparison over the whole plane, since it is not transitive: $(1, 0)$ is clockwise from $(0, 1)$, $(0, 1)$ is clockwise from $(-1, -1)$, and $(-1, -1)$ is clockwise from $(1, 0)$. So we first split the points into two half-planes, angles in $[0, \pi)$ and angles in $[\pi, 2\pi)$, and use the cross product only within the same half-plane, where no two angles differ by $\pi$ or more.

```cpp
HALF(p)
    if p.y > 0 or (p.y == 0 and p.x > 0)
        return 0
    return 1

LESS(p, q)  // p and q are already translated by -p[0]
    if HALF(p) != HALF(q)
        return HALF(p) < HALF(q)
    return p.x * q.y - q.x * p.y > 0

POLAR-ANGLE-SORT(P, p[0])
    for i = 1 to n
        P[i] = P[i] - p[0]
    MERGE-SORT P[1..n] using LESS as the comparison
    for i = 1 to n
        P[i] = P[i] + p[0]
```

Each comparison takes $O(1)$ time, so the procedure runs in $O(n \lg n)$ time.

> A **_polygon_** is a piecewise-linear, closed curve in the plane. A simple polygon is convex if, given any two points on its boundary or in its interior, all points on the line segment drawn between them are contained in the polygon's boundary or interior. A vertex of a convex polygon cannot be expressed as a convex combination of any two distinct points on the boundary or in the interior of the polygon.

## 33.1-8

> Show how to compute the area of an $n$-vertex simple, but not necessarily convex, polygon in $\Theta(n)$ time. (See Exercise 33.1-5 for definitions pertaining to polygons.)

Let the vertices be $p_1, p_2, \ldots, p_n$ in order along the boundary, and let $p_{n + 1} = p_1$. Define the signed area

$$S(P) = \frac{1}{2} \sum_{i = 1}^n p_i \times p_{i + 1}.$$

Computing $|S(P)|$ takes $\Theta(n)$ time. It remains to show that $|S(P)|$ is the area of $P$ even when $P$ is not convex.

**Translation invariance.** For any point $c$, let $s = \sum_{i = 1}^n p_i = \sum_{i = 1}^n p_{i + 1}$. Then

$$\sum_{i = 1}^n (p_i - c) \times (p_{i + 1} - c) = \sum_{i = 1}^n p_i \times p_{i + 1} - s \times c - c \times s = \sum_{i = 1}^n p_i \times p_{i + 1},$$

since $s \times c = -c \times s$. In particular, for a triangle, $S(\langle a, b, c \rangle) = \frac{1}{2} (b - a) \times (c - a)$, which is $\pm$ its area, positive if and only if $a, b, c$ is counterclockwise.

**Additivity.** If a diagonal $\overline{p_j p_k}$ splits $P$ into $P_1 = \langle p_j, \ldots, p_k \rangle$ and $P_2 = \langle p_k, \ldots, p_n, p_1, \ldots, p_j \rangle$, then $S(P) = S(P_1) + S(P_2)$: every edge of $P$ appears in exactly one of $P_1$ and $P_2$, and the extra terms $p_k \times p_j$ and $p_j \times p_k$ cancel. Both $P_1$ and $P_2$ keep the orientation of $P$.

Every simple polygon with $n > 3$ vertices has a diagonal (the two ears theorem), so by induction $P$ splits into $n - 2$ triangles, all oriented the same way as $P$. Their signed areas therefore all have the same sign, and $|S(P)|$ is the sum of their areas, which is the area of $P$.

The fan of cross products $\frac{1}{2} \sum_{i = 2}^{n - 1} (p_i - p_1) \times (p_{i + 1} - p_1)$ gives the same value by translation invariance with $c = p_1$. When $P$ is not convex, some fan triangles stick out of $P$ and get a negative sign, which is exactly why the argument above is needed instead of summing triangle areas directly.
